## 三、七条"合格 DSH Web 插件"门槛 · 逐条判定

| # | 门槛 | 依据 | 现状 |
|---|---|---|---|
| 1 | 是 npm 包，且声明 `dsh.bundle.patch` | package-manifest README | ✅ `"dsh": {"bundle": {"patch": "./cordis.patch.yml"}}` |
| 2 | 能一条命令装进 profile | plugin-manager README「An install command that names packages … is checked before pnpm runs」 | ✅ `dsh plugin --profile web add file:…` 已实机验证 |

| 5 | 声明兼容范围（`engines.dsh` 或 peerDeps） | app-boot README 原文 | ❌ **两者皆无** → 任何 dsh 版本都会尝试加载 |

## 四、P0 阻断项

### P0-1 `agent/turn-stopping` 载荷契约不符（静默失效）

**代码**（`lib/index.js:137-143`）：

```js
ctx.on('agent/turn-stopping', (session) => {
  lastSession = session ?? lastSession;
  if (cfg.autoReport && lastSession) void audit(lastSession);
});
```

**权威签名**（`api-catalog.js` 原文）：

```
'agent/turn-stopping'(this: Scoped<Agent>, payload: { agent: Agent; turn: number; signal: AbortSignal }): Promise<void> | void
```

**运行时分发**（`dsh-agent-loop/lib/index.js`）：

```js
await this.dispatch.serial("agent/turn-stopping", { turn, signal });
```

**后果链**：首参是 `{turn, signal}` 对象 → `lastSession` 被写成这个对象 → `audit()` 在 `const id = session?.header?.id` 处直接 `return null`（`lib/index.js:75-77`）→ **每个 turn 结束那次"最完整"的审计全部落空**；它还把 flush 拿到的真实 Session 覆盖掉了。

**为什么一直没暴露**：`lib/index.js:145-149` 的 `session/flush` 分支是对的（官方签名 `'session/flush'(this: Scoped<Session>, session: Session)`，`mode: 'parallel'` 的 awaited 持久化检查点），报告全靠它产出——`latest.txt` 23:22:28 的更新就是 flush 写的。**能出报告 ≠ 设计生效**。

**已复现**（`E:\aibuild\probe-turn-stopping.mjs`，用假 ctx + 与 `dsh-agent-loop` 相同的分发载荷）：

```
注册的 hooks = [ 'agent/turn-stopping', 'session/flush' ]
[turn-stopping] readSession 调用次数 = 0 | ids = []
[session/flush]  readSession 调用次数 = 1 | ids = ["sess-probe"]
```

即：turn-stopping 路径**一次都没触发审计**，flush 路径正常。

**改法**：删掉这个 hook，只保留 flush（推荐）。若要保留，必须取 `payload.agent` 上的会话，但 0.2.1-rc.2 的 asar 内全量 grep `agent.session` **0 命中**，Agent 未公开 session 访问器，所以 B 方案不可靠：

```js
// 推荐：删除 lib/index.js:137-143 整段，注释里说明"flush 已覆盖 turn 结束"
ctx.on('session/flush', (session) => {           // 保留，唯一触发点
  if (session?.header?.id) lastSession = session;
  if (cfg.autoReport && lastSession) void audit(lastSession);
});
```

### P0-2 兼容声明缺失（`engines.dsh` / `dsh.manifestVersion`）

- 现状：`package.json` 只有 `name/version/description/type/main/exports/files/dsh.bundle.patch/keywords/license`。
- 影响：无门控 → DSH 版本涨到 API 破坏时，插件照样被加载、静默出错；市场兼容缓存里该包 `facts.enginesDsh` 将为 `null`（对照：3,240 条中 781 条有值，如 `@linxin666/dsh-pet` → `>=0.2.1-rc.2`）。
- 改法：

```json
"engines": { "node": ">=22.19.0", "dsh": ">=0.2.1-rc.2" },
"dsh": { "manifestVersion": 1, "bundle": { "patch": "./cordis.patch.yml" } }
```

（`dsh-connect-workbuddy` 的 `engines` 写法是 `node: ^22.19.0 || >=24`，可对齐。）

### P0-3 许可与随包文件

- `packages/dsh-audit-plugin/` 与仓库根目录**都没有 `LICENSE` 文件**（`Get-ChildItem -Filter LICENSE*` 为空）；`files` 白名单只有 `["lib","cordis.patch.yml","README.md"]`。
- 后果：npm 包内没有许可证正文；仓库里已有的 `CHANGELOG.md`（14,718 B）**永远不会进包**。
- 改法：仓库根加 MIT 全文 `LICENSE`；`files` 补 `"LICENSE", "CHANGELOG.md"`；`package.json` 补 `repository`（`type: git` + `directory: packages/dsh-audit-plugin`）、`homepage`、`bugs`、`author`、`publishConfig`。

### P0-4 输出目录无界增长，`latest.txt` 会被非主会话覆盖

实机证据（`C:\Users\L0078\.dsh\dsh-audit\`）：

```
report-8d4f3a51-….txt    3,214 B   23:21:40   ← 一个 subagent 会话
report-a10af37f-….txt    8,337 B   23:21:56   ← 另一个 subagent 会话
report-session-85cd41c9-….txt 12,610 B 23:22:28 ← 主会话
latest.txt              12,610 B   23:22:28   ← 与主会话报告同尺寸（最后 flush 者胜）
```

- 每个 session（含 subagent；一次多代理任务可能几十个）都会留一个文件，没有上限、没有 TTL、没有清理。
- `latest.txt` 语义是"最近一次完整报告"，实际是"最后一次 flush 的那个会话"——一个 3 KB 的 subagent 报告可以把 12 KB 的主报告顶掉。
- `latest.txt` 首行只有 session id / preset / cwd，**没有生成时间**，用户无法判断新旧。
- 改法：① 仅当 `session.header.parentId == null`（顶层会话）才写 `latest.txt`；② 保留策略：每会话 1 份 + 全局最多 200 份 / 最旧 7 天；③ `latest.txt` 头部加 ISO 时间戳；④ README 写明输出体积增长。

### P0-5 README 不足以支撑市场发布

现有 55 行覆盖：安装、输出路径、报告结构、"只写文件无 UI"的取舍、口径、依赖、MIT。

缺失（市场用户与审核都会看）：
- **配置项表**：`enabled`、`autoReport`、`minIntervalMs`（默认 3000）、`outDir`（默认 `$DSH_HOME/dsh-audit`）、`debugShape`（默认 false）——五个字段一个都没写，用户只能读源码。
- **隐私说明**：报告会写入会话 id、工作目录、事件标签、工具名；`debugShape: true` 会 dump 首个事件的完整 data（可能含提示词内容）。应显式声明"不写 prompt 正文"与"debugShape 的副作用"。
- **兼容版本**：支持哪个 dsh 版本区间、依赖哪些实验性服务（`tokenMeter` 属于开发者预览）。
- **卸载/回滚**：`dsh plugin --profile web remove dsh-audit-plugin` + 目录清理。
- **示例输出片段 / 截图**：现在只有文字描述，用户不知道报告长什么样。
- **`icon` 字段**：`readPluginMeta` 支持根 `package.json.icon`（data URL）或 `<package>/icon`，缺了市场卡片就是默认占位图。

## 五、P1（发布前 1–2 周内应修）

**P1-1 `inject` 过宽，`tokenMeter` 实为硬依赖**
`export const inject = ['sessions', 'sessionQuery', 'tokenMeter']`（`lib/index.js:29`）。`sessions` 在代码里没有任何使用；官方失败矩阵规定「An injected service is unavailable → **Warn; continue while the entry waits for its dependencies**」——缺 `tokenMeter` 时插件**永远不激活**，而 `lib/index.js:111` 的 `try/catch` 降级永远走不到。
改：`inject: ['sessionQuery']`，把 `ctx.tokenMeter?.measure(session)` 包成可选能力，缺失时降级为"只用 `assistant/message.usage` 口径"并在报告里标注。

**P1-2 没有 `export const Config`，Web 设置页无法配置**
只能改 profile patch。作者注释的理由是"profile 里解析不到 `@deepseek-ai/*`"，但那属于 **peer** 问题：可以直接把 `@deepseek-ai/schemastery` 写成 `dependencies`（先例：`dsh-connect-workbuddy` 的 `dependencies` 里有 `"@deepseek-ai/schemastery": "3.18.4"`）。加了 `Config` 之后 `--dump-config-schema` 与插件设置面板才认得出字段。

**P1-3 写盘非原子 + `errors.log` 无轮转**
`mkdirSync` + `writeFileSync`（`lib/index.js:62-63`）直接覆盖 `latest.txt`：进程被杀/断电会留下半截文件；`errors.log` 只 append、永不修剪。官方有 `@deepseek-ai/dsh-atomic-write` 可用（workbuddy 插件即以 peer 方式依赖它）。

**P1-4 每 turn 全量重算**
`audit()` 每次都 `sessionQuery.readSession(id)` 读整个会话 jsonl 再 `analyze` 全量、同步渲染。本机会话已到 **1,071 事件 / 8.18M token**（`latest.txt` 实测），读+解析+渲染是同步 CPU，压在宿主事件循环上。改：缓存按 `header.lastSeq` 增量解析；至少把 analyze 放到 `queueMicrotask` 或分片 yield。

**P1-5 双份源码靠人工 sync**
`packages/dsh-audit-plugin/lib` 与仓库 `src/lib` 由 `scripts/sync-core.mjs` 拷贝 → 忘记 sync 就发布旧代码。改：core 提成 workspace 包（如 `@scope/dsh-audit-core`）由插件 `dependencies` 引用；或加 `"prepack": "node scripts/sync-core.mjs && node scripts/verify-pack.mjs"`，用 `npm pack --dry-run --json` 断言清单含 `LICENSE`/`CHANGELOG.md`/`cordis.patch.yml`。

**P1-6 无 CI**
`.github` 不存在。最小 workflow：`node --test`（现有 21 个测试）+ `npm pack --dry-run --json` 清单断言 + 版本号三方一致（根 `package.json` / 子包 / CLI）。

**P1-7 条目 id 与已发布包 `dsh-audit` 撞名**
`cordis.patch.yml` 的 `- id: dsh-audit`，而 npm 上 `dsh-audit` 是别人的「插件生态体检」插件。同时安装时 loader 条目 id 冲突，用户也会在市场里混淆。改：`- id: dsh-cost-audit  name: dsh-audit-plugin`（包名不用动），README 首段声明与 `dsh-audit` 的区别。

## 六、P2（0.7 目标）

- **最小 UI / CLI**：仓库里已有 `bin/dsh-audit.mjs`，但既没有 `bin` 字段也没进 `files`——发布后用户拿不到离线 CLI。当前"去 `%USERPROFILE%\.dsh\dsh-audit\` 翻 txt"对市场用户门槛过高；建议 `dsh-audit show` 子命令 + 设置面板里一行摘要。
- **英文 README**（`README.md` 全中文；`description` 已双语，市场英文用户会卡住）。
- **处方联动**：`"调低 compaction 压力阈值"` 现在是文字建议，可以直接产出可粘贴的 `cordis.patch.yml` 片段（与 `billion-context` 的 `compaction-basic` 配置对接）。
- **包名已确认可用**：`dsh-audit-plugin` 在 npm 上是 404（未被占），可以直接发布。
- **空会话被误判为"形状未适配"**（复现时发现）：`lib/adapter.mjs:31` 的候选探测是 `if (Array.isArray(value) && value.length > 0)` —— 真正空事件数组会被当成"形状未适配"抛错并写进 `errors.log`。新建会话/首个 flush 早于任何事件时会误报，把真错误淹掉。改：先判断"键是否存在"（`'events' in snapshot`），再区分"存在但为空"（合法空会话，直接跳过）。

## 九、附：值得记下的三个事实

1. **`dsh --dump-config` 不等于宿主实际加载集**。dshmarket 会通过运行中的 loader fiber 动态挂/卸（`.dsh-market/log.ndjson` 里 `toggle … fiber=true`），静态 dump 会漏掉运行时挂上的插件（本机 workbuddy 就是这条路径）。
2. **`measure().totalTokens` 不是账单**——这一点插件 README 已经写对，也是它区别于"猜 token"的唯一硬价值：`latest.txt` 里 `totalTokens 10,729 / surfaceTokens 2,512` 这类口径分离是可信的。
3. **市场兼容字段的真实分布**（3,240 条抽样）：`engines.dsh` 781 条 / peerDeps 2,216 条 / 两者皆空约 1,000 余条——"两处都不声明"在这个生态里不是少数派，但**声明 `engines.dsh` 的那批正是长期维护的插件**。
