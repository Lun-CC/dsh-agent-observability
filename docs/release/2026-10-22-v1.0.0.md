# dsh-audit-plugin v1.0.0 发布说明

**2026-10-22 · 首个公开发布**

```bash
dsh plugin --profile web add dsh-audit-plugin
```

装完即启用，每个 turn 结束自动审计，右下角「¥ 成本报告」打开报告页，
左上角不再是时间轴，而是一句话结论和可以直接点的整改按钮。

> 这个版本的含义是**发布面稳定**：npm 安装链路、报告文件格式、Web 路由、CLI 参数
> 从 1.0 起按语义化版本演进。`ctx.tokenMeter` 仍是宿主开发者预览能力，不在稳定性承诺内。

## 1.0.0 新增

- **离线 CLI 随包发布**：npm 包里带上 `bin/dsh-audit.mjs` 及它依赖的内核，不需要
  clone 仓库、不需要启动 DSH。装完插件后入口在 profile 的
  `node_modules/.bin/dsh-audit`（pnpm 本地链入，不在全局 PATH）：

  ```bash
  dsh-audit <会话目录>                        # 已把 profile 的 .bin 加进 PATH
  "$DSH_HOME/profiles/web/node_modules/.bin/dsh-audit" <会话目录>   # 直接写路径
  npx --yes --package=dsh-audit-plugin dsh-audit <会话目录>         # 不安装，一次性
  ```

  参数：`<session 目录 | .jsonl.zstd 文件>`、`--json`、`--tool-limit=<N>` / `--tool-limit N`
  （文本报告工具表最多列 N 条，默认 10）、`-h/--help`、`-V/--version`。
  退出码：`0` 至少一个会话成功，`1` 全部失败，`2` 参数错误；未知选项会明确报错。
  仓库根 `node bin/dsh-audit.mjs` 仍是真源，包内副本由 `scripts/sync-core.mjs` 生成，
  两者行为一致。
- **英文文档**：仓库根 `README.en.md` 与**包内** `packages/dsh-audit-plugin/README.en.md`
  （随 tarball 发布），覆盖 what / why-different / install / usage / output / privacy /
  config / compat / uninstall / limitations。
- **npm 元数据**：`author` 填 `lun`；`engines` / `manifestVersion` / `publishConfig` 与
  必需文件（含 `bin/dsh-audit.mjs`、`README.en.md`）由 `prepack` 静态校验。
  仓库已公开：<https://github.com/Lun-CC/dsh-agent-observability>，
  `repository`（插件包带 `directory`）/ `homepage` / `bugs` 均已指向该仓库。
- **运行时加固**：修掉 `errors.log` 里反复出现的
  `[route:register] /dsh-cost-audit webserver: duplicate exact route` —— 根因是插件
  dispose 时没有反注册 `webServer.register` / `tapIndex` 的路由（HMR、热挂载、配置重载都会
  再挂一遍）。现在保存 disposer、交给 Cordis effect 反注册，并对注入回调做幂等保护；
  写盘失败会清掉 `.tmp-*` 残留，不再被当成报告文件扫到。
- **安装/升级/卸载端到端验证**：在隔离 `DSH_HOME` 上对 npm tarball 走
  pack → install → load → report → upgrade → remove 全链路（含 UI 路由与 CLI）。
  0.11.0 基线与 1.0.0 最终包两轮的命令、退出码与结论都记录在
  `docs/evidence/2026-10-22-发布前安装卸载验证.md`（1.0.0 包 17 文件、SHA256
  `2B17F84…19CAD`）：安装 → 升级（0.11.0→1.0.0）→ 宿主页面 200 → 报告 → 卸载 → CLI
  全链路通过，`--dump-config` 中 `- id: dsh-cost-audit` 计数为 1，无重复注册。
- **发布手册**：`RELEASE.md`（发布前检查单、精确命令、回滚策略）。

没有破坏性变更：从 0.6.0 起的 bundle 安装方式、配置字段、报告文件命名都不变。

## 从 0.6 到 1.0：报告是怎么变成"能改"的

1.0.0 不是一次重写，是六版迭代的结果。

### 0.6 · 一条命令安装（2026-10-21）

此前的插件靠 profile patch 手工插入：能跑，但**在 Web UI 插件页根本不显示**，
也没法一条命令安装（`listBundles()` 只枚举 bundle 包）。0.6 改为官方 bundle 形态，
`dsh plugin --profile web add dsh-audit-plugin` 写依赖 + `dsh.profile.bundles`，装完默认启用。

### 0.7 · 发布就绪整改

按外部评审逐条修 P0/P1，其中一个是**静默失效**：`agent/turn-stopping` 的首参是
`{ agent, turn, signal }` 而不是 Session，那条审计路径从未触发过。现在只监听
`session/flush`（载荷即 Session，持久化检查点上 awaited）。同版补上
`engines.dsh` + `manifestVersion` 兼容门控、`LICENSE`/`CHANGELOG` 进包、
输出保留策略（`maxReports` / `maxAgeDays`）与 `errors.log` 轮转、
原子写、`latest.txt` 不再被 subagent 顶掉。

### 0.8 · Web 报告页

报告不再只躺在 `$DSH_HOME/dsh-audit/`：宿主端口上开 `/dsh-cost-audit/` 页面，
右下角加「¥ 成本报告」入口；桌面壳用 `webserver/index-inject` 内联脚本、
浏览器形态用 `tapIndex` 双通道注入；每次审计额外写 `report-<id>.json`/`latest.json`，
页面直接消费。

### 0.9 · 信息架构重做

按用户反馈：**一次对话 = 一条记录**（subagent 归到主会话下，不再平铺三条）；
**首屏只有三样东西**（几个数字 → 一句判断 → 几条建议），完整报告折叠；
建议卡只留「标签 + 动作 + 怎么改 + 可省多少」。顺带修了 0.7 的一个隐藏 bug：
`parentSession` 字段名写错导致 `isTopLevel()` 永远成立。

### 0.10 · 可执行整改

之前报告说"建议开 spill"，用户还得自己去翻配置。0.10 把处方映射到**真实存在的
配置项或项目约定文件**上：一键写入 `cordis.patch.yml`（spill 阈值、工具结果裁剪）
或 `AGENTS.md`（读取约定、环境事实），带预览、`.bak-<时间戳>` 备份、
按标记块撤销、幂等；Web 按钮与 `scripts/apply-fix.mjs` 共用同一份 `lib/fixes.mjs`。

### 0.11 · 修正 `read` 的假处方

平台 `spill-policy` 源码里 `read` 被写死豁免（`if (exec.name === 'read') return decision`），
read 的结果永远不会落盘 —— 所以对 read 建议"调低 spill 阈值"是假处方，
零收益。用平台的 spill 代码离线回放 11 个真实会话 / 343 条工具结果验证：
阈值 12500 时 0 条落盘；阈值 3000 时只有 3 条非 read 结果落盘，read 的两条原样不动。
现在插件只对非 read 工具开 spill 处方，read 的大结果改开「先定位、分段读」。

### 1.0 · 发布面收尾（本次）

CLI 入包（命令名 `dsh-audit`）、英文 README、npm 元数据、重复路由/写盘加固、
安装卸载验证、发布手册。功能面与 0.11 一致。

## 装完首屏能看到什么

- Web UI「插件」页出现 `dsh-audit-plugin`，默认启用
- 右下角「¥ 成本报告」→ `http://127.0.0.1:<dsh端口>/dsh-cost-audit/`
- 首屏：数字卡片 → 一句话判断 → 建议卡（右侧有「应用此修改」）
- 报告文件在 `$DSH_HOME/dsh-audit/`：`latest.txt/json`、`report-<id>.txt/json`、
  出错才有的 `errors.log`
- `latest.*` 只由顶层会话写，subagent 不会顶掉主报告

## 升级注意

从 0.11.0 升级是原地替换，无破坏性变更：

```bash
dsh plugin --profile web add dsh-audit-plugin@1.0.0
```

- 新装后包内 CLI 在 profile 的 `node_modules/.bin/dsh-audit`（来自插件包 `bin`）；
  把它加进 PATH 后可直接 `dsh-audit`，或直接用
  `npx --yes --package=dsh-audit-plugin dsh-audit` 跑
- 0.8.0 之前的历史报告只有 `.txt`，Web 页面读 `.json`；
  跑 `node scripts/backfill-summaries.mjs` 回填（用同一份日志重算，不伪造数字）
- 早期手工往 `cordis.patch.yml` insert 叶子插件的用户，请改回 bundle 方式安装，
  否则插件页仍然看不到
- Node 需要 `^22.19.0 || >=24`（内置 zstd 解压），DSH 需要 `>=0.2.0-rc.2`

## 卸载

```bash
dsh plugin --profile web remove dsh-audit-plugin
```

报告目录不自动删，需要时手动清理 `$DSH_HOME/dsh-audit/`。

## 隐私

报告只写会话 id、工作目录、事件类型标签、工具名、token 数，以及处方引用的调用序号；
**不写**对话正文、工具结果正文、系统提示正文。插件不发任何网络请求，数据不出本机。

两个需注意的开关：

- `debugShape: true` 会把 `readSession` 快照的首个事件完整 `data` 写进
  `debug-snapshot.json`，新会话的第一个事件可能是种子消息、**可能含提示词内容**；
  排查完请关掉并删除文件
- `errors.log` 会记录错误堆栈，堆栈里可能含文件路径

## 已知限制

- **token 两种口径**：账单以 `assistant/message.data.usage` 为准；
  `ctx.tokenMeter.measure().totalTokens` 不是账单（实测 10,729 vs 表面 2,512），
  逐节点归因看 `nodes[]`
- **`read` 被 spill 豁免**：调 `maxInlineTokens` 对 read 零收益（见 0.11）
- **compaction 剪掉的节点仍计入 carry**：日志无 compaction 事件，长会话滞留成本偏高
- **插件级 schema 归因未实现**：`ctx.tools.register()` 不暴露工具注册者
- token 估算按字符（CJK 1 字 ≈ 1 token），中文场景高估约 10–20%，报告里估算与实测分开标注
- 「无产出步」只抓工具全失败，抓不到"工具成功但结果无用"
- 每次 `session/flush` 全量重算；增量解析需要稳定 `header.lastSeq` 游标，尚未接入
- 没有 `export const Config`，所以没有 Web 设置面板，配置写 `cordis.patch.yml`

完整列表见根 `README.md`。
