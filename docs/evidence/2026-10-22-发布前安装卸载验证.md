### 1.2 DSH CLI 的正确调用方式（实测修正）

任务书给出的 `node "D:\tools\dph\resources\app.asar\dsh\node_modules\@deepseek-ai\dsh\lib\bin.js" <args>` **用普通 Node 不可用**（普通 Node 不识别 asar 虚拟路径）：

```text
Error: Cannot find module 'D:\tools\dph\resources\app.asar\dsh\node_modules\@deepseek-ai\dsh\lib\bin.js'
```

可用方式是用 Electron 的 `ELECTRON_RUN_AS_NODE` 跑同一个 `bin.js`；且 **`DeepSeek Harness.exe` 是 GUI 子系统程序**，直接 `& exe ...` 会立即返回、`$LASTEXITCODE` 为空、stdout 易丢失，必须 `Start-Process -Wait` 并重定向输出：

```powershell
$base = 'E:\workbuddybuild\build\.verify-release'
$env:DSH_HOME = "$base\dsh-home"
$exe  = 'D:\tools\dph\DeepSeek Harness.exe'
$bin  = 'D:\tools\dph\resources\app.asar\dsh\node_modules\@deepseek-ai\dsh\lib\bin.js'
$args = @('--expose-internals', $bin, '--profile', 'web', '--dump-config')

$p = Start-Process -FilePath $exe -ArgumentList $args -Wait -PassThru -NoNewWindow `
      -RedirectStandardOutput "$base\out.log" -RedirectStandardError "$base\err.log"
"exit=$($p.ExitCode)"
Get-Content "$base\out.log" -Encoding utf8    # 必须 -Encoding utf8，否则中文乱码
```

别的坑：本机 shell 是 PowerShell 5.1，`Start-Process` **没有 `-Environment` 参数**（先用 `$env:DSH_HOME=...` 再启动）；`$home` 是只读自动变量，改用 `$vhome` 之类。

### 1.3 隔离 profile 的构造方式

`dsh-app-boot/lib/index.js` 的 `PROFILE_TEMPLATES` 中 `web` 模板 = `["@deepseek-ai/dsh-base", "@deepseek-ai/dsh-web-app"]`；`loadProfile` 在 profile `package.json` 不存在且名字命中模板时会自动初始化。因此在隔离 `DSH_HOME` 里直接用 profile 名 `web`（首次执行 `--dump-config` 或 `plugin ... add` 时自动创建）即可得到与官方一致的 web 组合，**无需复制真实 profile**：

```json
{"name":"dsh-profile-web","private":true,"dependencies":{},
 "dsh":{"profile":{"bundles":["@deepseek-ai/dsh-base","@deepseek-ai/dsh-web-app"]}}}
```
