# dsh-audit-plugin

Session-level cost audit for DeepSeek Harness (**1.0.0**). On every session flush it
attributes tokens to the steps and nodes that consumed them, prescribes concrete fixes,
and serves a Web report page with "Apply this fix" buttons.

Not the same as npm `dsh-audit` (plugin-ecosystem health checks); mount id is
`dsh-cost-audit` to avoid loader id collisions. Both can be installed together.

Repository / issues: <https://github.com/Lun-CC/dsh-agent-observability>
(source in `packages/dsh-audit-plugin`; offline CLI at repo root `bin/dsh-audit.mjs`).

## Requirements

| Item | Requirement |
|---|---|
| Node | `^22.19.0 || >=24` (built-in zstd) |
| DSH | `>=0.2.0-rc.2` (`engines.dsh`; verified on 0.2.0-rc.2 / 0.2.1-rc.2) |
| Required service | `sessionQuery` |
| Optional service | `tokenMeter` (developer preview; degrades gracefully) |
| Package form | bundle (`dsh.bundle.patch` + `manifestVersion: 1`) |

## Install

```bash
dsh plugin --profile web add dsh-audit-plugin
```

It appears in Web UI → Plugins → Installed, enabled by default; audits on every
`session/flush` (persistence checkpoint after a turn) — no manual trigger.

Local development (`link:` fails halfway; use `file:`):

```bash
dsh plugin --profile web add file:<absolute-path>/packages/dsh-audit-plugin
```

After editing `src/lib`, run `node scripts/sync-core.mjs` and restart dsh.
Upgrade with `dsh plugin --profile web add dsh-audit-plugin@latest`. Pre-0.8.0 reports are
`.txt` only; backfill `.json` via `node scripts/backfill-summaries.mjs`.

## Bundled CLI

The package ships `bin/dsh-audit.mjs` (generated by `scripts/sync-core.mjs` from the repo
root, identical behavior), so install gives you an offline CLI. Its entry point is the
profile's `node_modules/.bin/dsh-audit` (pnpm links it; add it to PATH, call it by path, or
prefix commands with `npx --yes --package=dsh-audit-plugin --`). No DSH, API key or network
needed:

```bash
dsh-audit ~/.dsh/sessions/<group>/session-xxxx   # one session
dsh-audit ~/.dsh/sessions --tool-limit=5               # top N tools in the report
dsh-audit ~/.dsh/sessions --json                       # machine-readable
dsh-audit --help                                       # usage / options / exit codes
dsh-audit --version                                    # 1.0.0
```

Flags: `<session dir | .jsonl.zstd file>`, `--json`, `--tool-limit=<N>` / `--tool-limit N`
(top N tools, default 10), `-h/--help`, `-V/--version`; unknown options error. Exit codes:
`0` ≥1 success, `1` all failed, `2` bad args (missing target / path not found / bad value).
Without installing: `npx --yes --package=dsh-audit-plugin dsh-audit <dir>`. The CLI has no
platform pricing section — that needs the in-host `tokenMeter`.
The target may be the sessions root, a group dir, a session dir, or a single `.jsonl.zstd`
file: it recurses up to 3 levels looking for `*.jsonl.zstd` (no fixed two-level layout
assumed; newest mtime wins when several logs share a dir). Quote paths with spaces/CJK.

### Uninstall

```bash
dsh plugin --profile web remove dsh-audit-plugin
Remove-Item -Recurse -Force "$env:USERPROFILE\.dsh\dsh-audit"   # data dir is kept
```

## What you see

- A **"¥ 成本报告"** button (bottom-right) →
  `http://127.0.0.1:<dsh-port>/dsh-cost-audit/`
- First screen: number cards → one-sentence verdict → prescription cards
  (label / action / how / estimated saving); full report folded into `<details>`
- Conversations grouped, subagents folded into their parent; self-contained page
  (no external assets), light/dark aware
- Each prescription has "Apply this fix" with preview, backup and revert

Routes: `GET /dsh-cost-audit/` (page), `GET /api/list` (reports + latest +
`profile` candidates and `lastError`), `GET /api/report?id=`, `POST /api/fix`
(`preview` / `apply` / `revert`; pass `profile` when several profiles are
installed, otherwise it refuses with the candidate list), all on the host's
`ctx.webServer`.

## Output

```
$DSH_HOME/dsh-audit/latest.txt|.json        latest top-level report (generation time inside)
$DSH_HOME/dsh-audit/report-<sessionId>.txt|.json   per-session report
$DSH_HOME/dsh-audit/errors.log              only on errors
$DSH_HOME/dsh-audit/debug-snapshot.json     only with debugShape: true
```

`latest.*` is written only by top-level sessions (`parentSession`/`parentId` empty and
`delegationDepth === 0`), so subagents never overwrite it. Retention: `maxReports` (200)
files / `maxAgeDays` (7) days; `errors.log` rotates at 256 KiB; writes are temp-file + rename.

## Fixes

| Prescription | Target |
|---|---|
| context only grows | `cordis.patch.yml` → enable `tool-result-pruner` |
| results not spilled | `cordis.patch.yml` → `spill-policy.maxInlineTokens: 3000` (**no effect on `read`**) |
| reading too much at once | project `AGENTS.md` reading conventions |
| barren steps | project `AGENTS.md` environment facts |

Writes append a marked block (`# >>> dsh-cost-audit:<id>` … `# <<<`), back up to
`<file>.bak-<timestamp>`, are idempotent, and can be reverted. Config changes need a DSH
restart. CLI equivalent: `node scripts/apply-fix.mjs --list|--id=spill|--revert`.

## Configuration

In the profile's `cordis.patch.yml` (`$DSH_HOME/profiles/<profile>`):
`- id: dsh-cost-audit` → `config:` → override keys below; verify with
`dsh --profile web --dump-config`.

| Key | Default | Meaning |
|---|---|---|
| `enabled` | `true` | plugin loads but does nothing when false |
| `autoReport` | `true` | write a report on every `session/flush` |
| `minIntervalMs` | `3000` | per-session debounce between audits |
| `outDir` | `$DSH_HOME/dsh-audit` | output directory (`null` derives it) |
| `maxReports` | `200` | retain at most N reports |
| `maxAgeDays` | `7` | delete reports older than N days |
| `maxErrorLogBytes` | `262144` | rotate `errors.log` above 256 KiB |
| `debugShape` | `false` | dump first event `data` (privacy risk) |
| `debugTriggers` | `false` | log trigger reasons |
| `ui` | `true` | serve the Web page and entry button |

## Privacy

Reports contain session id, working directory, event type labels, tool names, token counts,
and tool-call sequence numbers — no prompts, tool-result bodies, or system-prompt text.
`debugShape: true` writes the first event's full `data` (possibly prompt text) to
`debug-snapshot.json`: use briefly, then delete. `errors.log` may contain stack traces with
file paths. Nothing is uploaded; the plugin makes no network requests.

## Metrics

Billing totals: `assistant/message.data.usage`; per-node attribution:
`ctx.tokenMeter.measure().nodes[]`. `totalTokens` is **not a bill** (envelope included;
measured 10,729 vs 2,512). `baseline.kind`: `none` / `estimated` / `usage`. Tool tokens are
char estimates (CJK ≈ 1 token/char).

## Known limitations

- `read` is exempt from `spill-policy`; lowering `maxInlineTokens` does not affect it.
- Compaction-pruned nodes still count toward carry cost.
- No per-plugin schema attribution (`ctx.tools.register()` exposes no registrar).
- Char-based estimates overestimate Chinese content by ~10–20%.
- Every flush re-analyzes the whole session (sync CPU); no `Config`, no settings panel.
- With the plugin installed in several profiles, "apply" writes to the most recently
  modified profile; check the path shown on the page (use Preview if unsure).
